# RedisVL Integration

> **Status: SHIPPED.** The RedisVL integration is an *escape hatch* into
> [`redisvl`](https://github.com/redis/redis-vl): it converts a Redis OM
> model into a RedisVL index and hands you the full redisvl query API —
> without duplicating any of it. Advanced search (`FT.HYBRID`,
> aggregations, vector policies) stays in redisvl; Redis OM keeps owning
> models, persistence, and its own query operators.

## Installation

RedisVL is an **optional** dependency — Redis OM imports cleanly without
it, and the helpers below raise a helpful `ImportError` only when called:

```bash
pip install 'pyredis-om[redisvl]'   # requires redisvl >= 0.25.1
```

## What you get

| Helper | What it does |
| --- | --- |
| `to_redisvl_schema(Model)` | Converts the model's RediSearch schema into a redisvl `IndexSchema` (index name, key prefix, storage type, field types — all faithful to what OM's `Migrator` creates). |
| `get_redisvl_index(Model, async_client=True)` | Returns a ready-to-use redisvl `AsyncSearchIndex` (or sync `SearchIndex`) wired to the model's `Meta.database`. |
| `hybrid_search(index, query, timeout=None)` | Runs a redisvl `HybridQuery` (`FT.HYBRID`, Redis 8.4+) with **Redis Cluster support** — redisvl itself cannot route `FT.HYBRID` on a cluster. |

Import from the async package (`aredis_om`) or the generated sync
package (`redis_om`) — both expose the same three helpers:

```python
from aredis_om.redisvl import get_redisvl_index, hybrid_search, to_redisvl_schema
# sync: from redis_om.redisvl import get_redisvl_index, hybrid_search, to_redisvl_schema
```

## Quickstart

Define the model exactly as you always do — the only requirement is
`index=True` (class-level or per-field):

```python
from aredis_om import Field, JsonModel, VectorFieldOptions


class Article(JsonModel, index=True):
    title: str = Field(index=True)
    body: str = Field(full_text_search=True)
    embedding: list[float] = Field(
        vector_options=VectorFieldOptions.flat(
            type=VectorFieldOptions.TYPE.FLOAT32,
            dimension=384,
            distance_metric=VectorFieldOptions.DISTANCE_METRIC.COSINE,
        )
    )
```

Create the index **with either engine** — the generated schema is
interchangeable, so you can let OM's `Migrator` manage it (as usual) or
create it directly through redisvl:

```python
from aredis_om.redisvl import get_redisvl_index

index = get_redisvl_index(Article)   # wired to Article's Meta.database
await index.create(overwrite=True)   # or: await Migrator().run()
```

Then use the full redisvl query API against your OM-saved documents:

```python
from redisvl.query import VectorQuery

results = await index.query(
    VectorQuery(
        vector=embed("light running shoes"),
        vector_field_name="embedding",
        num_results=10,
    )
)
```

## Hybrid search (BM25 + vector)

`FT.HYBRID` combines full-text BM25 ranking with vector similarity in a
single server-side query (Redis 8.4+, redis-py 7.1+). Use the
`hybrid_search()` helper rather than `index.query()` — it adds the
cluster routing that redisvl is missing:

```python
from redisvl.query import HybridQuery

from aredis_om.redisvl import hybrid_search

results = await hybrid_search(
    index,
    HybridQuery(
        text="running shoes",
        text_field_name="body_fts",    # OM renders full-text fields as <name>_fts
        vector=embed("running shoes"),
        vector_field_name="embedding",
        combination_method="LINEAR",
        linear_alpha=0.5,              # 0 = pure vector, 1 = pure BM25
    ),
)
```

### Why the `_fts` suffix?

A field declared `Field(full_text_search=True)` is rendered by OM as
**two** RediSearch fields: `body` (TAG, for exact filtering) and
`body_fts` (TEXT, aliased to the same JSON path / hash field). Point
redisvl text queries at the `_fts` name — the exact spelling OM's own
`Migrator` creates, so an OM-migrated index and a redisvl-created index
behave identically.

### Redis Cluster

An index name hashes to a single cluster slot, so `FT.HYBRID` must be
pinned to one node. redisvl ships cluster helpers for `FT.SEARCH` /
`FT.CREATE` but not for `FT.HYBRID`; `hybrid_search()` fills that gap by
mirroring redisvl's own routing. The optional `timeout` argument
(milliseconds) is applied on cluster clients only.

## Still delegated to redisvl (use the index directly)

The escape hatch gives you the *entire* redisvl API through the returned
index object — these are not re-wrapped by OM:

- **`FT.AGGREGATE`** — server-side group-by / reduce / sort / limit via
  `index.aggregate(AggregateQuery(...))`.
- **Vector field policies** — compression, runtime tuning knobs.
- **Embedding cache and LLM helpers** — see the
  [redisvl docs](https://docs.redisvl.com/).

Note: `VectorFieldOptions` exposes the `FLAT` and `HNSW` algorithms.
Redis 8.8's SVS-VAMANA index is not exposed through OM's model
declarations — configure it through redisvl directly if you need it.

## What changes for existing users?

Nothing. The integration is **additive**:

- All existing Redis OM features continue to work unchanged.
- redisvl is never pulled in unless you install the extra *and* call the
  helpers.
- The schema conversion is read-only — it never mutates your model or
  migrates your index behind your back.
